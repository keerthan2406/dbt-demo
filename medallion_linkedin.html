I built a metadata-driven medallion pipeline on Databricks and dbt. What ties it together is a control table that every step reads from and writes to. The goal was to take daily files from a landing volume to analytics-ready tables, with history, tests and an audit trail at every step. Ingestion runs as a Databricks job, transformation runs in dbt, and the two only talk to each other through that table. That keeps each side simple and makes every run easy to trace. How it works: 1. A Databricks Asset Bundle job reads a config table and loads daily CSVs from a Unity Catalog volume into bronze tables (COPY INTO, all columns as strings, audit columns added). 2. Every load is logged to a control table: entity, layer, status, batch id, rows, duration. 3. dbt does not start until that table says bronze succeeded. An on-run-start macro checks the latest batch for the load date and stops the run if anything is missing or failed. 4. dbt cleans the data in staging (trim, standardise, dedupe, map codes with seeds), then handles history in silver: append, SCD1 merge, and SCD2 with a dbt snapshot. 5. Gold has the dimensions, facts, a daily sales table and one big table for BI. 6. An on-run-end macro writes every model and test result back to the same control table. Quality checks run at every layer: not_null, unique, relationships, custom generic tests, and dbt_utils tests. With dbt build, a failed test skips everything downstream. Built to ship: everything lives in Git (branches and pull requests), and the bundle has separate dev and prod targets with their own catalogs. The same code is ready to promote through a CI/CD pipeline, with prod running on a schedule.
